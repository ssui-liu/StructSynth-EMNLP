# Novelty 写作优化计划：Abstract / Introduction / Contribution

> **核心原则**：让读者在看到任何方法细节之前，就已经被说服"结构发现是 low-data 表格合成的核心瓶颈，而现有方法都没有正面解决它"。StructSynth 的出现是对这一瓶颈的必然回应，而非众多可能的模块组合方案之一。

---

## 总体叙事重构

### 当前叙事线（方法描述型）
> 问题存在 → 三类方法各有局限 → 我们提出 StructSynth → 两阶段框架 → 实验好

### 目标叙事线（洞察驱动型）
> Low-data 下的核心瓶颈是结构发现（而非生成能力） → 现有方法都没有正面解决这个瓶颈（三种不同的回避方式） → 解法的关键是 decouple（降低每阶段的样本复杂度） → StructSynth 是这一洞察的具体实现 → 实验验证

叙事线的变化不需要改动方法本身，而是重新组织已有信息的呈现顺序和因果关系。

---

## Step 1：Introduction 第一段 — 重建因果层次

> 这是读者形成第一印象的地方，决定了他们用什么框架理解全文。

### 当前问题
将结构发现失败、图学习不可靠、生成模型过拟合并列为同等地位的困难，没有建立因果层次。读者读完只觉得"low-data 下很多东西都不好用"，但不知道瓶颈到底在哪。

### 改写目标
建立三层因果链：**依赖结构是价值所在 → 结构发现在 low-data 下首先崩溃（first-order 瓶颈） → 生成质量下降是其下游后果**。读者读完应接受"结构发现是核心瓶颈"这个前提。

### 具体步骤

1. **保留**领域背景开头（healthcare/finance/education + 依赖关系的价值），无需大改
2. **重写**中间的困难描述，按因果层次组织：
   - 第一层：表格数据的价值来自特征间的依赖结构（已有，保留）
   - 第二层：Low-data 下，依赖结构的发现首先崩溃——统计检验失去 power，图学习算法产出不可靠的结构（将其定位为 first-order 瓶颈，而非与其他困难并列）
   - 第三层：因此，无论下游生成模型多强，没有可靠的结构基础，合成数据都无法保持原始依赖
3. **改写**段末结论句：从"合成数据应保持依赖关系"改为"有效的合成方法必须首先解决结构发现这个上游瓶颈"

### Rubric

| 维度 | 通过标准 | 未通过的信号 |
|------|---------|-------------|
| 因果层次 | 读者能清晰区分"上游瓶颈"（结构发现）和"下游后果"（生成质量），两者不是并列关系 | 结构发现的困难与生成模型过拟合仍然以 "A, B, and C" 的平行句式呈现 |
| 瓶颈定位 | 段末明确指向"结构发现"为核心瓶颈，而不是笼统地说"数据稀缺是挑战" | 段末仍是泛泛的 "data scarcity poses a fundamental challenge" |
| 铺垫效果 | 读完此段后，读者自然会问"那现有方法是怎么处理结构发现的？"——为第二段创造了阅读期待 | 读者的期待仍然是"现有方法各有什么缺点？"（泛泛的 survey 心态） |
| 篇幅控制 | 段落长度与当前版本基本持平（±2 句） | 为了解释因果链而显著增加篇幅 |

## Step 2：Introduction 第二段 — 统一失败模式

> 直接决定 reviewer 是否认为 decouple 有意义。如果三类方法的失败被统一归因，decouple 就是必然解法；如果仍是平行列举，decouple 只是"一种可能的设计"。

### 当前问题
三类方法（DGMs / Structure-aware / LLMs）的批判是独立的、平行的。读者看完感受是"各有各的毛病"，而非"它们犯了同一个错误"。

### 改写目标
将三类方法的失败重新组织为**同一个统一维度——"如何处理结构发现"**的三种不同回避方式。段末用一句话提炼出共同失败模式。

### 具体步骤

1. **新增**一句总括开头：现有方法都没有正面应对结构发现这个上游瓶颈，而是以不同方式回避了它
2. **重写**三类方法的批判，每类围绕"如何处理结构发现"展开：
   - DGMs：将结构发现与生成合并为端到端过程 → low-data 下两者**同时崩溃**
   - Structure-aware：将结构发现作为前置步骤，但依赖纯统计方法 → 小样本下结构本身就不可靠，**错误传播到生成阶段**
   - LLMs：完全跳过显式结构发现，依赖文本序列化中的隐含依赖 → **没有利用表格数据的结构性特征**
3. **新增**一句统一总结：这些方法要么将结构发现和生成耦合（两阶段共享样本瓶颈），要么完全绕过结构发现
4. **改写**过渡句：从"These limitations motivate a discover-then-synthesize paradigm" 改为强调 decouple 是对"耦合"这一共同失败模式的直接回应

### Rubric

| 维度 | 通过标准 | 未通过的信号 |
|------|---------|-------------|
| 统一视角 | 三类方法的批判围绕同一个维度（"如何处理结构发现"）展开，读者能看到共性而非三个独立问题 | 三类方法仍以 "A does X but..., B does Y but..., C does Z but..." 的独立平行结构呈现 |
| 共同失败模式 | 段落中有一句明确的总结句，提炼出"耦合"或"回避"作为统一失败模式 | 段落结束时只是列完三类方法的各自缺点，没有归纳 |
| 过渡自然性 | 从"统一失败模式"到"decouple 的提出"之间有清晰的因果推导，读者感觉 decouple 是唯一合理的回应 | 过渡句仍然是 "These limitations motivate..." 这种泛泛的连接 |
| 批判精准度 | 每类方法的批判聚焦在结构发现维度，不引入与主线无关的缺点 | 批判中混入了与结构发现无关的问题（如计算成本、可扩展性等），稀释主线 |

## Step 3：Introduction 第三段 — 从洞察到设计的推导

> 让两阶段设计成为洞察的必然推导，而非"又一个两阶段系统"。

### 当前问题
直接介绍 StructSynth 的两阶段设计，跳过了"为什么 decouple 是正确的解法"的论证。读者容易将其归类为工程组合。

### 改写目标
在介绍方法之前，先用 1-2 句声明 decouple 的理论动机；然后说明解耦框架下每个阶段如何利用互补信号解决各自子问题；最后才引出 StructSynth 的具体设计。

### 具体步骤

1. **上移**当前 method section 中的核心论点：将 "reduce per-stage sample complexity" 从 method 开头提升到此处，作为 decouple 的理论动机
2. **新增** 1-2 句设计逻辑：
   - 解耦后，结构发现阶段可以融合 LLM 语义先验与统计信号来克服小样本不稳定性（两种信号互补）
   - 生成阶段可以将已发现的结构作为硬约束（executable blueprint）而非软注意力来保证依赖忠实度
3. **精简**当前的两阶段描述：既然设计动机已经交代清楚，具体实现的描述可以更简洁
4. **确保**从 Step 2 的"统一失败模式"到此处的"decouple 解法"有清晰的逻辑衔接

### Rubric

| 维度 | 通过标准 | 未通过的信号 |
|------|---------|-------------|
| 动机显性化 | 读者能在方法描述之前看到 decouple 的理论动机（降低样本复杂度），而非事后解释 | "reduce per-stage sample complexity" 仍然只出现在 method section 中 |
| 设计必然性 | 两阶段设计从洞察中自然推导而出，读者感觉"只能这么做" | 两阶段设计仍然读起来像"我们选择了这种方式"（design choice 而非 design necessity） |
| 互补性论证 | 能看到每个阶段利用了什么独特的信号/机制来解决其子问题 | 只描述了每阶段做什么，没有解释为什么这样做能解决 Step 1 中定义的瓶颈 |
| 篇幅平衡 | 动机论证 ≤ 方法描述的篇幅；整段不超过当前版本 +3 句 | 动机论证过长，挤压了方法描述的空间，或整段显著膨胀 |

## Step 4：Contribution 列表 — 增加洞察层

> 决定 reviewer 在评分时如何定位贡献。当前只有"方法+实验"两层，缺少 insight-level 的声明。

### 当前问题
两个 contribution：(1) 提出框架（纯方法描述）；(2) 实验效果好。Reviewer 评估时会直接将 C1 与已有 work 对比，判定"不新"。

### 改写目标
扩展为三层递进结构：**洞察 → 方法 → 验证**。让 reviewer 先评估"问题诊断对不对"，再评估"解法合不合理"。

### 具体步骤

1. **新增 C1（洞察层）**：声明核心发现——low-data 表格合成中，结构发现（而非生成模型拟合能力）是性能退化的核心瓶颈，现有方法因耦合/回避结构发现而无法有效应对
2. **改写 C2（方法层）**：从当前的"提出 discover-then-synthesize 框架"改为紧扣洞察的表述——基于这一发现，提出 StructSynth，通过解耦降低每阶段样本复杂度；结构发现阶段融合语义先验与统计信号；生成阶段将结构作为可执行蓝图
3. **改写 C3（验证层）**：保留实验贡献，增加对设计假设的验证——不仅展示 SOTA 结果，还通过消融实验验证了解耦设计中每个阶段的独立贡献

### Rubric

| 维度 | 通过标准 | 未通过的信号 |
|------|---------|-------------|
| 洞察层存在性 | Contribution 列表中有一条独立的、不涉及方法描述的洞察/诊断声明 | 所有 contribution 都以 "We propose..." 开头 |
| 洞察可评估性 | 洞察声明足够具体，reviewer 能判断"同意/不同意"（如：瓶颈是结构发现而非生成能力） | 洞察声明过于笼统（如：我们发现 low-data 下有挑战） |
| 方法-洞察关联 | 方法层 contribution 明确回指洞察（如 "Based on this finding, we propose..."），每个设计选择都有对应动机 | 方法层 contribution 与洞察层没有逻辑连接，读起来像独立的两条 |
| 三层递进 | 读者能感受到"诊断问题 → 提出解法 → 验证假设"的递进关系 | 三条 contribution 读起来仍是平行的"我们做了 A/B/C" |
| 篇幅控制 | 三条 contribution 的总篇幅不超过当前两条的 1.5 倍 | 为了增加一条而使列表过长、冗余 |

## Step 5：Abstract — 前置核心论点

> 决定 reviewer 带着什么心理预期读全文。Abstract 是 Introduction 叙事的压缩版，在 Introduction 定稿后回头调整。

### 当前问题
Abstract 的叙事结构与 Introduction 相同：平行列举三类方法缺陷 → 直接跳到方法。缺少核心诊断的前置。

### 改写目标
在 ≤6 句的篇幅内传递完整的洞察驱动叙事：瓶颈定位 → 统一诊断 → 解法动机 → 方法概要 → 实验结果。

### 具体步骤

1. **改写 S1**：从"数据稀缺限制了合成"改为"表格数据的价值源于依赖结构，low-data 下这些结构的发现首先崩溃"——一句话建立核心瓶颈
2. **改写 S2**：从平行列举三类方法缺陷，改为统一诊断——点明它们共同的失败模式是"耦合或回避结构发现"
3. **改写 S3**：在引入 StructSynth 时加入 decouple 的动机——不只说"解耦了两个阶段"，还要说"为什么解耦"（降低每阶段的样本需求）
4. **精简 S4-5**：两阶段描述适度压缩（Introduction 和 Method 中会展开），留出空间给前面的洞察表述
5. **保留 S6**：实验结果句保持不变

### Rubric

| 维度 | 通过标准 | 未通过的信号 |
|------|---------|-------------|
| 瓶颈前置 | 前两句内出现"结构发现是瓶颈"的明确表述 | 前两句仍然在泛泛地说"数据稀缺是挑战" |
| 叙事完整性 | 6 句以内覆盖：瓶颈 → 现有方法为何失败 → 为什么 decouple → 怎么做 → 结果 | 某个环节缺失（最常见：缺"为什么 decouple"） |
| 与 Introduction 一致 | Abstract 的叙事线是 Introduction 的忠实压缩，无矛盾 | Abstract 中的诊断或批判角度与 Introduction 不一致 |
| 篇幅控制 | 总长度不超过当前 Abstract 的 110% | 为了增加洞察表述而显著超长 |

## Step 6：交叉检查与一致性

> 所有局部修改完成后的全局校验。

### 检查项

1. **Abstract ↔ Introduction 一致性**
   - Abstract 中的诊断（瓶颈定位、统一失败模式）与 Introduction 的展开完全对应
   - 用词一致（如"耦合""解耦""结构发现瓶颈"等关键表述在两处使用相同术语）

2. **Introduction ↔ Related Work 一致性**
   - Introduction 中对三类方法的重新批判（围绕结构发现维度）与 Related Work 的详细讨论不矛盾
   - Related Work 中 LLM-Assisted Dependency Discovery 段落的区分点应从"连接了两阶段"更新为"让结构发现在 low-data 下首次可靠可用"

3. **Contribution ↔ 实验 支撑性**
   - C1 声明的洞察（结构发现是瓶颈）需要在实验中有对应验证（如消融实验中去掉结构发现的性能退化）
   - C2 声明的"降低样本复杂度"需要在 robustness-to-sample-size 实验中有支撑

4. **Method Section 动机上移后的衔接**
   - 确认 method 开头的 (a)(b)(c) 三点在 "reduce per-stage sample complexity" 上移后仍然通顺
   - 避免 Introduction 和 Method 中出现重复表述

5. **因果性声明的边界**
   - 保留 DAG 功能性表示的 footnote 声明
   - 检查改写后的措辞中是否意外引入了因果性声明（如 "causal structure" 等应替换为 "dependency structure"）

### Rubric

| 维度 | 通过标准 | 未通过的信号 |
|------|---------|-------------|
| 术语一致 | 核心概念（瓶颈、耦合、解耦、结构发现）在 Abstract/Intro/Method 中使用相同术语 | 同一概念在不同位置用不同词描述，造成歧义 |
| 逻辑无矛盾 | Introduction 的批判视角与 Related Work 兼容 | Introduction 说某类方法"完全回避结构发现"，但 Related Work 中对同类方法有更细致的描述暗示其也做了某种结构处理 |
| 声明有支撑 | 每一条 contribution 声明都能在实验部分找到对应的证据段落 | 某条声明（如"降低样本复杂度"）在实验中无直接支撑 |
| 无因果越界 | 全文不出现 "causal" 或暗示因果性的表述（除了 Related Work 中引用他人工作时） | 改写后意外引入了因果性声明 |

## 附：改写顺序建议

| 顺序 | 步骤 | 原因 |
|------|------|------|
| 1 | Step 1 — Intro 第一段 | 因果层次是全文叙事的根基，后续所有修改依赖这里建立的前提 |
| 2 | Step 2 — Intro 第二段 | 统一失败模式紧接因果层次，两段合在一起构成完整的问题论证 |
| 3 | Step 3 — Intro 第三段 | 从问题论证过渡到方法引入，需要在前两段定稿后才能写好衔接 |
| 4 | Step 4 — Contribution | 是 Introduction 论证的压缩总结，需要在主体段落定稿后提炼 |
| 5 | Step 5 — Abstract | 是全文叙事的最终压缩，应在 Introduction 完全定稿后回头调整 |
| 6 | Step 6 — 交叉检查 | 所有局部修改完成后的全局一致性校验 |
